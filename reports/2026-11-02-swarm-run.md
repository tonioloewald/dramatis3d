# Dramatis: first swarm run, log

Kept as it happens, for the owner's agents post. Times are local (2026-11-02, evening).

## Setup
- Goal: get as far as possible without touching tosijs-3d, push to a private repo, and let the owner take stock in the morning. The first-release bar: the site exports a character that works in three.js.
- Targets set during the run by the owner: three.js and Unity first, then Godot added (free and open source). Unreal is secondary.
- Recorded rule: general code bound for tosijs-3d is prototyped in `src/upstream/` and moved before it ships. It's tracked as `upstream:tosijs-3d` tasks in the dramatis3d project only, so tosijs-3d isn't interrupted.

## Revision 1 (launched, then stopped)
- Shape: foundation → five parallel lanes (skinned GLB, three.js embed, share + licences, site + creator, extremes sweep) → engines (spike 1, VRM, three.js loads the GLB) → integrate → two reviewers → fix + push.
- Foundation finished: package, strict TS, a no-Babylon guard shown able to fail three ways (runtime import, type-only import, transitive type leak through tosijs-3d/rigged-body), CI, Pages, the site skeleton.
- The five lanes had started when the owner relayed outside advice: territories, contracts first, gate 1 as the shared definition of done, one reviewer for shared docs, check integration early.
- Gaps the advice exposed in revision 1:
  - No contracts. The exporter, the three.js adapter and the site would each have invented their own interfaces (the site agent was told to write a placeholder seam the exporter didn't know about).
  - Several lanes wrote docs pages, and nobody owned the nav or index.
  - Integration came only at the end.
- Stopped minutes after the lanes started. No commits were lost: all five branches still pointed at the scaffold, and one worktree had one uncommitted file.

## Revision 2 (resumed from cache: the foundation wasn't re-run)

  - `test/gate1/`, an acceptance harness that reports "not run" rather than passing silently, and is shown able to fail

## The run, in numbers
- Revision 2 used 13 agents: foundation (from cache), contracts, five build lanes, the fit check, three engine lanes, integrate, and the docs owner. No errors, nothing skipped. About 2h05m wall clock, 2.38M subagent tokens, 1,139 tool calls.
- End state on main, re-checked by the orchestrator after the run:
  - `bun run check`: 235 pass, 28 skip (the network, browser and engine tiers), 0 fail.
  - `bun run gate1`: 43 pass, 0 fail. All 6 gate checks pass on all 4 exported samples.
- Beyond gate 1:
  - three.js: creator → View in three.js → viewer, with the character walking on a UAL clip, in headless Chromium (SwiftShader). The e2e suite passes 7/7.
  - Godot 4.5: 32/32.
  - Blender 5.2: 28/28.
  - Babylon 9.33: 28/28.
  - Unity: a sample project and a batch script, never run (no editor installed).
  - Unreal: steps only.

## What the advice bought, with evidence
- **Territories held completely.** The fit check found zero textual merge conflicts across five lanes. The engine-phase merges onto main were conflict-free too.
- **Contracts paid off where they were complete.** The three-viewer lane: "the handoff contract was complete … the viewer plugged in with zero changes on either side."
- **Every real mismatch was semantic and invisible to git.** The fit check's words: "the cost is that every real mismatch was semantic and invisible to git … only running real data across the boundary found them." It found six:
  1. `hideClothes`: the licence lookup honours it, the builder ignores it, so export fails on a valid file.
  2. The creator offered all 160 pack proxies, but only 44 are licensed to ship. Fixed by filtering, and the creator is visibly thinner for it.
  3. Quaternius hair is offered and licensed, but the build refuses it.
  4. The extremes lane read licences straight from the pack JSONs and recommended community items that the licence lane excludes.
  5. A provisional licence table against the real manifest. The ids agreed exactly, and the table was replaced.
  6. Duplicated logic: two copies of tosijs-3d's `coverBody` tuck (export and extremes) that disagree about a 3 cm edge fade. Both exist because tosijs-3d mixes pure geometry with engine code in one module.
- **The early fit check made final integration cheap.** The integrator: "cheap because work/fit had already done the semantic seam work and every engine-phase lane had built on work/fit."

## What went wrong or cost time (from the agents' retros)
- **Two rule sources disagreed.** The computed brief said shared files take dependencies only. LANES.md, written by the contracts agent, allowed minimal edits to `site/config.ts`. Four lanes hit this. Lesson: one source of rules, not two.
- **A build that writes a tracked file.** `bun run build` regenerates the toc in `site/docs/docs.md`, a shared file, so every lane that built dirtied it and had to revert. Four lanes reported it.
- **Contracts drifted from the profile.** The VRM TSDoc said "look-at from the eye joints". The profile says look-at is by expression, because UAL has no eye joints.
- **The profile contradicted itself.** "Lowest point of the skin at y = 0" conflicts with removing covered skin when shoes delete the soles. Found by Blender reporting the lowest vertex.
- **The contracts left a gap.** `buildCharacter` must return licences, but the only licence function was another lane's stub. The exporter invented a provisional table to get unblocked. The fit check found it and replaced it.
- **Environment friction:**
  - The worktree sandbox refused compound shell commands (heredocs, `$(...)`, even paths containing the word "source"), so many edits were redone through Write and Edit.
  - Agents shared a scratchpad and overwrote each other's temp files.
  - Agent worktrees inside the repo let prettier walk into them.
  - Generating dev TLS certificates was denied by the permission classifier, so `bun start` never ran. The static build was checked instead.
- **The docs owner's lesson:** "each lane's page was accurate about its own lane but stale about the others." Next time each lane should list the claims its page makes about other lanes, and the docs should use one status vocabulary (Verified / Draft / Not run) from the start.

## For next time
1. Commit a real exported sample with the contracts, so gate 1 runs before the exporter lands. The contracts agent suggested this.
2. One source of lane rules, generated into each brief, plus a named fit lane with its own territory (who owns `test/fit/` was unclear).
3. Builds must not write tracked files.
4. Worktrees outside the repo; unique scratch directories per agent.
5. The fit check is the most valuable single step: it's the only place semantic mismatches surface. Run it as early as there is anything to fit.
