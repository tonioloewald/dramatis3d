## Nits

*Fixed before the tag:* `src/build/settings.test.ts` now asserts every default the build reads exists in tosijs-3d's `DEFAULT_CHARACTER` with the type the build expects; it fails with a read key renamed (checked by hand, then reverted).

- **(unverified, correctness)** `src/build/settings.ts:38`: `DEFAULTS` is cast from `DEFAULT_CHARACTER` (`Record<string, any>`). The "fills in" test compares each setting to that same object. If a key were renamed or dropped upstream, it would give `undefined` defaults typed as `string`, and the test would still pass (`undefined === undefined`). Gate 1 would not catch it either, because the samples set their settings explicitly. This is a test-strength gap, not a current defect.
