## Fix before the tag (verified majors)

- [ ] **CLAUDE.md says "Nothing is built here yet" and "No code, package.json, build or tests yet ... add the real commands here then"** (`CLAUDE.md:7`, and the Status section at lines 15-17). Found by both the docs and dx lenses. AGENTS.md only defers to this file, so every agent session starts from a false picture of the repo and gets no commands. Commit 2cf6dab updated the README but missed this file. **Fix:**
  - Replace both passages with the current state.
  - Point to the README's Commands table and to LANES.md.
  - Name `bun run check` as the definition of done.
  - Add the `bun run tls` (mkcert) step for `bun start`, the three `DRAMATIS_*` test tiers, the fact that src/upstream is never exported, and the Bun 1.4.2 pin.

  **Check that clears it:** add a doc test that fails when CLAUDE.md contains "Nothing is built" or "No code" while package.json exists. Reverting the fix must turn it red.
- [ ] **CI and Pages never run the 28 env-gated tests** (`.github/workflows/ci.yml:36`, `pages.yml`). Export is the launch gate, yet nothing that rebuilds a character from code runs in CI. CI's gate 1 checks only the frozen `samples/out/` GLBs. So a regression in buildCharacter or in the CDN human pack ships green. **Fix:**
  - Add a CI job that runs `DRAMATIS_NETWORK=1 bun test`.
  - Add a job that installs Playwright Chromium and runs the viewer e2e with `DRAMATIS_BROWSER=1 DRAMATIS_NETWORK=1`.
  - Make the Pages deploy depend on CI passing (`workflow_run` or a shared job).
  - The engines tier stays manual: record its last green run in the release checklist or in `reports/spike-1.md`.

  **Check that clears it:** a CI run log showing the network and browser jobs executing, not skipping, their tests. Then a branch with a deliberately broken buildCharacter turns CI red and Pages does not deploy.
- [ ] **The GLB container code has five readers, three writers, three accessor readers and two bin builders, and they have drifted** (`src/vrm/glb.ts:19`, `test/gate1/glb.ts`, `src/upstream/extremes/hair-library.ts`, `src/three/fixture-character.ts`, `site/creator/actions.ts`, `src/upstream/glb/skinned-glb.ts`).
  - gate1 takes the last JSON chunk while the VRM path takes the first.
  - gate1's accessor reader crashes on sparse accessors, which skinned-glb emits.
  - hair-library and ualRest skip the length and version checks.
  - The writers disagree on an empty BIN chunk.
  - The "Test-side only" `test/gate1/glb.ts` is imported by `src/build/*` and `tools/engines/*`.

  The result: the gate checks exports with a reader the shipped code does not use. **Fix:**
  - Write one GLB chunk module containing the union of the guards: length, magic and version checks, first JSON chunk wins, short-read guard, optional bin, empty bin omitted on write, sparse-aware accessor read.
  - Put it at `src/glb.ts`, or in `src/upstream/glb/` so it moves with skinned-glb to tosijs-3d (#3662).
  - Point the test harness, tools, hair-library and skinned-glb at it.
  - Replace `glbLicences` and the header parse in ualRest with `tosijs-3d/glb-manifest` `parseGlbJson`.

  **Check that clears it:** unit tests on the shared module for a duplicate JSON chunk (first wins), a sparse morph accessor, a file under 12 bytes (clean "not a GLB" error) and an empty bin (omitted). Then `grep` finds a single `0x46546c67` magic constant and gate 1 still passes.
