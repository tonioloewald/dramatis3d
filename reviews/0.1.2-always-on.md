### Minor

- [ ] **(unverified) The creator -> View in Unity e2e test passes even when the handoff fails.** `site/viewer/viewer.e2e.test.ts:425`, lens correctness.
  - How it fails: in `site/unity/main.ts` `start()`, a null or throwing `takeHandoff(id)` sets an "expired" status, then falls through to `fromCharacter(DEFAULT_CHARACTER)`.
  - That build resets `error` to false, sets a truthy `name` and binds all four gaits. Every assertion the test makes still passes.
  - The three.js twin of this test does assert `s.source === 'handoff'`.
  - The handoff did work in this run (the screenshot shows `character`), so this is a gap in the test, not a live defect.
  - Fix: expose `source` on `dramatisUnity` as the viewer does and expect `'handoff'`. At minimum, assert `u.name !== 'Default character'` and that the status never contained "expired".
  - Clears when: the test goes red with `takeHandoff` stubbed to return null.

### Nit

- [ ] **(unverified) `viewIn` HEAD-probes `/unity/`, not the Unity Web build.** `site/creator/actions.ts:209`, lens correctness.
  - How it fails: if `site/unity/player/Build` is missing, `/unity/index.html` still answers 200. The creator reports "Opened … in the Unity player", but the new tab says the player isn't built, and the handoff entry sits in IndexedDB until its 24h TTL runs out.
  - It is latent: the player build is committed today.
  - Fix: give `ViewTarget` an optional probe path (e.g. `/unity/player/Build/player.loader.js`) for `UNITY_PLAYER`.
  - Also add a unit test for `viewIn`'s "not on this site" message. No test covers it for either target; `creator.test.ts` tests only `shareLink`.
