## Blockers

### B1. `src/upstream/held-parts.ts` ships in the library (docs + blast-radius, verified)
- **Where:** `src/build/write.ts:21` imports `../upstream/held-parts` (387 lines). `writeCharacterGlb` and `exportCharacterGlb` are exported from `src/index.ts`.
- **What a release would publish:** the module is inside `dist/index.js` (line 3480 `// src/upstream/held-parts.ts`, line 3623 `function heldParts`), and `dist/upstream/held-parts.d.ts` is in `npm pack --dry-run`.
- **Rules it breaks:**
  - `src/upstream/README.md` rule 4: "never a published second copy".
  - The README's own entry for this file: "It must move before a Dramatis release ships it."
  - The CLAUDE.md invariant: "moved before it ships".
  - The CHANGELOG [Unreleased] line "Dramatis's copies in src/upstream/ are gone, and with them the last code bound for tosijs-3d" is false at HEAD.
- **Structural risk:** tosijs-3d main already has `heldParts` (10db09438, today), and its `riggedBodyGlb` routes through it, but no tosijs-3d release contains it; the pinned 0.12.5 has no `heldParts`. If Dramatis ships now, held items on the mesh path use tosijs-3d's copy and held items on the MakeHuman path use Dramatis's. A later fix to grip placement upstream would then reach only one of the two body types. The copy Dramatis tests (`src/mesh/mesh.test.ts`) is the one due for deletion.
- **Fix, choose one:**
  - (a) Release tosijs-3d 0.12.6 with `heldParts`, bump the exact pin, import it from the tosijs-3d subpath in `write.ts`, delete `src/upstream/held-parts.ts`, regenerate the samples and re-run `bun run gate1`.
  - (b) The owner records an explicit keep-decision. The README rule and the CHANGELOG sentence then say that this release ships the copy and drops it at the next tosijs-3d release.
- **Either way:** add a guard that fails when a public entry's bundle reaches `src/upstream/`, with an allowlist for deliberate keeps (see the follow-up below).
- **Re-review scope:** correctness + blast-radius over the remediation diff. If option (a) is taken, also gate 1 over the regenerated mesh and held samples.

  - *Residual risk:* an attacker-supplied GLB link can exhaust the victim's tab memory, or leak the victim's IP and timing to a third host, until the loader refuses external URIs. There is no data exposure from the victim's origin.

  - *Disposition:* card.
  - *Residual risk:* none reachable today, because fetch uses the same WHATWG parser and fails first.
